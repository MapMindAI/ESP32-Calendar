## What this is

ESP-IDF firmware for an ESP32-S3 desk calendar built on a Waveshare 4.2" reflective-LCD board
(board id `S3_RLCD_4_2`). The display is a 400×300 **1-bit black/white** panel driven over SPI;
LVGL renders in RGB565 and `main.cpp` thresholds each pixel down to one bit on flush.

The code is still recognisably the vendor's factory self-test demo (`project(03_Fac)`, screens that
cycle through SD-card / Wi-Fi / BLE / codec checks). Treat that demo as scaffolding being replaced
by calendar functionality — see §10 for what is residue and what is real.

## 1. Docs

| Doc | Covers |
|---|---|
| `README.md` | Board specification, the peripherals this firmware drives and their pins, build/flash quickstart, vendor and datasheet links |
| `doc/user_interface.md` | Display constraints, the one-screen/four-container view model, every widget and what updates it, button gestures and bindings, fonts and assets |

Ship doc updates with the code, not as a follow-up:

* New or changed screens, widgets, label semantics, or button bindings → `doc/user_interface.md`.
* New peripheral, pin change, or a change to what is attached → the hardware tables in `README.md`.
* New design/protocol notes go in `doc/`; link them from the table above and from `README.md`.

## 2. Toolchain and build

ESP-IDF **v5.5.x** (`IDF_PATH=~/esp/esp-idf`, currently v5.5.2), target `esp32s3`. Source the export
script first in any shell that builds: `. $IDF_PATH/export.sh`.

| Command | Use |
|---|---|
| `idf.py build` | Full build; output is `build/03_Fac.bin` |
| `idf.py reconfigure` | Re-resolve managed components after editing `main/idf_component.yml` |
| `idf.py -p /dev/ttyACM0 flash monitor` | Flash + serial log (port varies; ask rather than guess) |
| `idf.py save-defconfig` | The **only** way to update `sdkconfig.defaults` after a `menuconfig` change |
| `idf.py size-components` | Check flash/RAM impact before adding a component |

* Never commit `sdkconfig` or `sdkconfig.old`. A config change that should stick goes through
  `idf.py save-defconfig` so it lands in `sdkconfig.defaults`.
* Adding a managed dependency means editing `main/idf_component.yml`, running `idf.py reconfigure`,
  and committing the resulting `dependencies.lock` diff.

## 3. Architecture and concurrency

Boot order in `app_main` is load-bearing — `UserApp_AppInit()` allocates the PSRAM audio buffer and
brings up I2C/RTC/codec/SD/ADC/Wi-Fi **before** the panel and LVGL exist, then the UI is built under
the LVGL lock, then tasks start:

```
UserApp_AppInit()  →  RlcdPort.RLCD_Init()  →  Lvgl_PortInit()  →  [lock] UserApp_UiInit() [unlock]  →  UserApp_TaskInit()
```

Rules that follow from it:

* **Every LVGL call from outside the LVGL task must be wrapped in `Lvgl_lock(...)` / `Lvgl_unlock()`.**
  The LVGL task runs on core 0 at priority 5; app tasks run pinned to core 1. Several inherited tasks
  in `user_app.cpp` call `lv_label_set_text` unlocked — that is a bug, not a pattern. Add the lock when
  you touch such a task; don't copy the unlocked form into new code.
* Cross-task signalling in this codebase is FreeRTOS **event groups** (`BootButtonGroups`,
  `GP18ButtonGroups`, `CodecGroups`, `wifi_even_`) and one queue (`ble_queue`). Stay with those
  primitives rather than introducing globals-plus-polling.
* Large buffers go in PSRAM (`heap_caps_malloc(..., MALLOC_CAP_SPIRAM)`): the 1bpp framebuffer, both
  LVGL full-frame buffers, the pixel lookup tables, the 288 KB audio buffer. Internal RAM is scarce —
  assert every allocation, as the existing code does.
* Wi-Fi and BLE are **not** coexistent here: `Lvgl_WfifBleScanTask` deinitialises Wi-Fi
  (`espwifi_deinit()`) before `ble_stack_init()`, and deinitialises BLE when done. If you need both
  at once you are changing the radio strategy — say so explicitly, don't slip it in.
* `disp_drv.full_refresh = 1`: every flush repaints and re-transmits the whole panel. Partial-update
  work is a real change to `display_bsp`, not a driver flag.

## 4. Hardware map

Pins and I2C addresses currently live in **three** places: `main/user_config.h` (defines, included
nowhere), literal constructor arguments in `main.cpp` (`DisplayPort(12,11,5,40,41,400,300)`) and
`user_app.cpp` (`I2cMasterBus(14,13,0)`, `Rtc_Setup(&I2cbus,0x51)`), and `codec_board/board_cfg.txt`
for the codec/I2S pins.

| Function | Pins / address |
|---|---|
| Reflective LCD (SPI3) | MOSI 12, SCK 11, DC 5, CS 40, RST 41, TE 6 |
| I2C bus 0 | SDA 13, SCL 14 — SHTC3 @0x70, PCF85063 @0x51, ES8311 @0x18, ES7210 @0x40 |
| I2S (codec) | MCLK 16, BCLK 9, WS 45, DIN 10, DOUT 8, PA enable 46 |
| SD (SDMMC 1-bit) | CLK 38, CMD 21, D0 39 |
| Buttons | BOOT GPIO0, user GPIO18 (both active-low) |
| Battery ADC | ADC1 channel 3 |

If you touch pin configuration, **consolidate toward `main/user_config.h` and actually include it**
rather than adding a fourth copy. Codec and I2S pins stay in `board_cfg.txt` — that file is the
codec_board component's own format.

## 5. Generated and vendored code

Do not hand-edit:

* `components/ui_bsp/generated/**` — GUI Guider output. UI changes belong in the GUI Guider project;
  behaviour that must live in code goes in `components/ui_bsp/custom/` or `user_app.cpp`. If a
  generated file must be patched to build, say so explicitly in the commit message — it will be lost
  on the next regeneration.
* `components/ExternLib/SensorLib/**`, `components/ExternLib/codec_board/**` (except the
  `S3_RLCD_4_2` entry in `board_cfg.txt`, which is this board's), `components/port_bsp/src/multi_button/**`.
* `managed_components/**` — gitignored and regenerated; changes there vanish.

## 6. Validation before committing

There is no automated test suite and no host-side test harness. Validate in this order, matching what
changed:

1. `idf.py build` must succeed with no new warnings from files you touched.
2. Flash and watch `idf.py monitor` through a full boot: no `ESP_ERROR_CHECK` aborts, no allocation
   asserts, no task watchdog or stack-overflow panics.
3. Exercise the paths you touched on the device — display refresh, button single/double/long press,
   SD read-back, RTC/SHTC3 label updates, record→playback, Wi-Fi/BLE scan counts.
4. If you changed allocation sizes or added a component, check `idf.py size-components` and confirm
   the 8 MB app partition still fits.

Report honestly which of these you actually ran. "Builds clean, not flashed" is a fine and useful
result; claiming device validation you didn't do is not.

## 7. Scope discipline

* This is one firmware for one board. No board-abstraction layer, no runtime target selection, no
  compatibility shims for hardware that isn't on the desk.
* A drive-by cleanup inside a file you're already editing is fine; sweeping renames or reformatting
  across `components/` ship separately — mixed diffs are unreviewable on a codebase with no tests.
* Don't reformat inherited vendor code (the brace style and tab/space mix in `port_bsp` and
  `user_app`) as a side effect of a functional change.
* Keep the layering: `user_app` → `app_bsp` → `port_bsp`. Don't call `driver/` APIs straight from
  `user_app`, and don't put application/UI logic into `port_bsp`.

## 8. Prefer the simplest design that solves the concrete problem

No abstraction layers, configurable knobs, or extension points "in case we need them later". Drop any
proposal bullet starting with "this also lets us…" or "leaves room for…". On a device with one
400×300 mono panel and a fixed set of sensors, a direct implementation is the right implementation.

New managed dependencies need a reason stated in the commit message — each one costs flash on a
partition that's already committed to 8 MB.

## 9. Naming and style

* Match the file you're in. `port_bsp`/`app_bsp` use `ClassName::Method_Name()` and
  `Module_FunctionName()`; C shims use `snake_case`. Don't introduce a fourth convention.
* New files, functions, and macros get unabbreviated names. Keep the abbreviations already
  established here (`bsp`, `lcd`/`rlcd`, `i2c`, `adc`, `pcm`, `ui`, `sd`) rather than re-deriving new ones.
* Comments in this repo are a mix of Chinese and English. Write new comments in English; leave
  existing Chinese comments alone unless you're rewriting that code anyway.
* UI strings are currently bilingual (a Chinese label plus an English label per state). Keep both
  populated when you add a state.

## 10. Known residue from the factory demo

Flag these rather than quietly preserving them; several are things a calendar build should remove:

* `esp_wifi_bsp.c` hardcodes SSID `PDCN` and a plaintext password. Any real Wi-Fi work means moving
  credentials to NVS/provisioning — never add another hardcoded credential.
* `Rtc_SetTime(2026,1,5,14,30,30)` runs on **every** boot in `UserApp_AppInit()`, so the RTC never
  actually keeps time. Fix this before building anything date-dependent on top of it.
* `Lvgl_SDcardTask` writes `waveshare.com` to `/sdcard/sdcard.txt` and reads it back as a self-test.
* `espressif/avi_player` and `espressif/esp_new_jpeg` are declared in `main/idf_component.yml` and
  linked by `app_bsp`, but nothing calls them — dead weight, safe to drop if nothing needs video.
* `SensorLib` is linked from `port_bsp` for the PCF85063 RTC alone.
* `sdkconfig.old` is checked in but gitignored going forward — it's a stale artifact, not a reference.
* The project is still named `03_Fac`. Renaming it changes the binary name and every flashing recipe,
  so do it deliberately, on its own, not as part of another change.
